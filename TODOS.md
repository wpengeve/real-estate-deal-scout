## P1 — Real data source integration

**What:** Replace `fixtures/listings.json` with a live real estate data source.

**Why:** The MVP pipeline is built and validated against fixture data. Real value requires real listings.

**Pros:** Transforms the tool from a demo into a working investment screener.

**Cons:** Adds an API key dependency and requires mocking in tests.

**Context:** The `fetch_listings()` interface is already abstracted — only `tools/fetch.py` changes. No other tool is affected. Candidates: RapidAPI Zillow wrapper (fastest path, unofficial), Bridge Interactive MLS (legitimate, requires membership application ~2-4 weeks). The RapidAPI Zillow wrapper is the recommended starting point for personal use.

The `RawListing` model now includes `lot_sqft`, `home_type`, `school_district`, and `hoa_fee`. These fields must be mapped from the real data source response. Zillow's API typically returns: `lotAreaValue` (lot sqft), `homeType` (home type), `monthlyHoaFee` (HOA). School district data may require a separate lookup (e.g. GreatSchools API or geocoding to district boundary).

**Effort:** M (human ~2d / CC ~30min)

**Depends on:** MVP pipeline working end-to-end with fixture data.

## P1 — Rent comps data source

**What:** Replace the hardcoded `estimated_monthly_rent` field in fixture data with a real rent comps source.

**Why:** Cap rate and cash-on-cash return calculations require a reliable rent estimate. Without it, financial analysis cannot run.

**Pros:** Enables accurate financial analysis on real listings.

**Cons:** Adds another API dependency and potential cost.

**Context:** For MVP, `estimated_monthly_rent` is hardcoded in `fixtures/listings.json`. Production options:
- Zillow Rent Zestimate — likely bundled in RapidAPI Zillow response as `zestRent` (free with RapidAPI plan)
- Rentometer API — dedicated rent comps, paid (~$30/mo), more granular
- HUD Fair Market Rents — free, ZIP-level, less precise

**Effort:** S (human ~1d / CC ~15min)

**Depends on:** Real data source integration (above).

## P2 — Async enrichment

**What:** Switch `enrich_neighborhood()` to `async` with `asyncio.gather()` for concurrent WalkScore + FEMA lookups.

**Why:** Sequential API calls on 50 listings takes ~25-60 seconds. Async reduces this to ~2-3 seconds.

**Pros:** Dramatically faster pipeline runs with real data.

**Cons:** Requires pytest-asyncio in test suite, minor refactor of orchestrator caller.

**Context:** Write `enrich_neighborhood()` as `async def` from day one — even if awaited sequentially in MVP. This costs nothing now and avoids a painful refactor when real data lands. The fix when needed is one line: `await asyncio.gather(*[enrich(l) for l in listings])`.

**Effort:** S (human ~4h / CC ~10min)

**Depends on:** Real data source integration (above).
