1. What this project is

Real Estate Deal Scout is an agentic pipeline that surfaces high-conviction real estate investment deals. You describe what you want (plain English or config.yaml); the system fetches live listings, screens them, enriches each with neighborhood data (rent, schools, solar, zoning, tax assessment), runs personalized financial analysis (cap rate, cash-on-cash, cash flow computed for your down payment and rate), flags risks, and uses an LLM to rank and narrate the top deals. It ships as both a CLI (scout.py) and a web app (app.py, FastAPI).

The core idea: Python does the math, the LLM only ranks and explains. Every number a user sees comes from deterministic code — the LLM never invents financials.

2. The mental model — one pipeline, six stages

Everything revolves around this flow. Stages 1–5 are deterministic Python; stage 6 is the only place an LLM is involved, and even then only for ordering and prose.

#StageInput → OutputWhere
1Fetchconfig → list[RawListing]tools/fetch.py
2Screenlistings + criteria → filteredtools/screen.py
3Enrich+ rent, walk score, schools, solar, tax/zoningtools/enrich.py
4Analyzecap rate, CoC, cash flow, zoning, appreciationtools/analyze.py
5Flag risksflood, seismic, wildfire, DOM outlierstools/risks.py
6Rank + narrateflagged → Shortlist w/ thesistools/*_ranker.py

pipeline.py is the orchestrator that wires these six stages together.

4. How the code is written — the design principles

Five ideas that recur everywhere. Understanding these is understanding the base of the project.

4.1  Pydantic models are the contract

Every stage takes a typed model in and returns one out (models.py). Data shape is validated at every boundary, config errors surface early, and any intermediate result serializes to JSON — which is how --from-analyzed re-runs ranking without re-fetching.

4.2  Graceful degradation is non-negotiable

Every external call returns None/empty and logs rather than raising. A missing API key never crashes the pipeline — you get partial enrichment. Codified as policy in CLAUDE.md. It's why the tool works end-to-end with zero paid keys.

4.3  The LLM never touches the numbers

Rankers receive already-computed financials and only order deals + write prose. Hallucinated addresses are rejected; every metric comes from analyze.py. This is the project's integrity guarantee.

4.4  Aggressive caching to protect API budgets

In-process dict caches (geocode, crosswalk, solar, schools, HUD) for a run's lifetime, plus a file-based TTL cache (data/scraperapi_cache/) so re-runs don't burn paid credits.

4.5  Data-sourcing preference order

From CLAUDE.md: already-in-a-page-we-fetch → free public API → free-tier-with-key → paid (needs approval). Paid deps are flagged with a TODO, never integrated autonomously. Running cost stays near zero by design.

4.6  Async where it pays, sync where it doesn't

Enrichment is async (httpx.AsyncClient, asyncio.gather, semaphores, shared client) because it fans out many calls per listing. Risk lookups are sync — a deliberate MVP simplification.

5. The two entry points

CLI — scout.py

python scout.py                 # run from config.yaml
python scout.py --chat          # describe criteria in plain English
python scout.py --market "Portland, OR" --max-shortlist 10
python scout.py --from-analyzed outputs/…_analyzed.json   # skip slow enrichment

Loads/validates config → optional chat intake → pipeline.run() → prints a rich panel per deal (price, cap rate, cash flow, zoning stars, narrative).

Web — app.py (FastAPI)

A full web app — more built-out than the roadmap docs suggest:

  • Chat UI (/) backed by web_chat.ChatSession
  • Magic-link auth — /api/auth/request → token → /auth/verify → session cookie
  • Background runs — POST /api/run starts, GET /api/run/{id} polls status
  • Report serving — GET /reports/{run_id} returns the generated HTML
  • History — logged-in users see past runs

Live runs & chat sessions live in in-memory dicts; SQLite (db.py) holds durable users, sessions, and run records. Reports persist on disk, pruned after 7 days on startup.

7. Configuration & ranking

config.yaml drives a run without touching code. Key knobs:

  • fetch.data_source — fixtures | csv | redfin | scraperapi | rentcast
  • criteria.* — price, beds, DOM, HOA, home types, allowed_cities radius filter
  • financial_assumptions.* — down payment %, loan rate, vacancy, mgmt fee (these personalize every metric)
  • output.ranker — mock (offline) | ollama (local) | claude (best)
  • purpose — rental (cap rate / CoC) vs primary (PITI-only)
Ranker trade-off: mock is instant & free but crude; ollama is free but ranks poorly; claude is the quality target (needs the API key — the current top TODO).

8. Testing

pytest, ~217 tests, one file per tool plus test_pipeline.py for integration. External APIs are mocked. Per ROLES.md, QA is always-on: the full suite must pass before every commit.
